# Dashboard source

Build with Node.js 18 or later. No npm install, package downloads, framework compiler, or production Node server is required.

```sh
npm --prefix frontend run build
npm --prefix frontend test
python scripts/prepare_dashboard.py --output dist/source-ui
```

`frontend/dist/` is ignored. `build.mjs --output <directory>` supports packaging directly into a staging UI directory. `prepare_dashboard.py` and the Debian packager run the same builder; set `PPGW_NODE` if Node is outside PATH. Output filenames contain the first 12 SHA256 characters of their content, and `manifest.json` describes the entry and assets. Text sources use LF for stable Windows/Linux builds. Rebuilding removes only the previous manifest's generated asset basenames, then emits the current graph. It never recursively deletes an output directory.

## Source boundaries

- `src/shell.js`, `auth.js`, and `shell.css` own login, navigation, history guards, mobile controls, appearance selection. Authentication retains the `PaoPaoGateWay` storage shape and unrelated preferences. SHA256 works on HTTP LAN origins without WebCrypto. A 401 offers an inline login panel that retains editor drafts. The sidebar has three compact icon buttons for system (default), light, and dark appearance. System changes apply live; selection preserves the current route and draft. Retired custom colors are cleared.
- Settings and source selection have one authority: `integration/gateway.js`, `gateway_view.html`, and `gateway.css`. They are built directly. The shell supplies public mount/navigation/runtime hooks.
- `src/editor.js` owns the subscription form and `src/model.js` owns lossless document edits. The model retains every imported field; controls change only fields the user touches. `_clash_id` stays attached through edits and ordering. Copies remove the identity to create a new row. Clash provider structure and existing rule kinds remain restricted. PPsub supports provider plans, groups, rules, global monitor, Shadowsocks input, scheduled restarts, import/export, and extension JSON.
- `integration/ppsub_panel.js` remains the sole persistence/preview/task implementation. The source form implements its public `mount({header, exportConfig, importConfig, providers})` contract and retains its locking, revision checks, provider polling, update plans, task recovery, and navigation protection.
- `src/diagnostics.js` and `diagnostics.css` own the diagnostics and recovery route. Diagnostics reports and backups load on demand; only the requested backup page is checked. Restore/recovery require a fresh signed impact preview and explicit confirmation. An uncertain submission only polls its original job ID. Session storage retains the ID/action alone, and a reload returns to that task. Navigation, logout, browser Back, and unload share the pending task guard. A polling 401 retains the job and reauthentication resumes it; an explicit submit 4xx rejection unlocks the page for a new preview. Completion distinguishes verified, inactive, and staged acceptance and explains any preserved worker service state. Reports are projected onto fixed public fields and enums before display/export.
- `src/overview.js` and `overview.css` own the overview page. A direct overview visit does not load the compatibility runtime. It retains traffic/CPU/memory histories and tooltips, per-core frequency, process usage and uptime, NIC addresses and link details, DNS/ACL/features, GEO version and optional debug connection-pool counters. Read-only dynamic requests run sequentially every second; full facts refresh every 30 seconds or on a boot change. Counter resets start a fresh rate window; unavailable rates display a dash. Hidden tabs pause requests, leaving the page aborts requests and disposes observers, and late responses cannot remount it. A polling 401 pauses until the shared inline login succeeds. All API strings render as text.
- `src/proxies.js`, `proxy-model.js`, and `proxies.css` own the proxy page. A direct visit does not load the compatibility runtime. Selector switches, automatic-group locks/unlocks (including smart groups), temporary GLOBAL/rule mode, URL-specific latency tests, provider updates/healthchecks, subscription usage and allowlisted node details use the existing APIs. Ordinary automatic-group clicks never switch a node. Group tests release an existing lock before testing; failed releases stop the batch. Batch tests use at most eight concurrent requests, stop queued work after a 401 or disposal, and never resume a mutation after reauthentication. Only matching old connections are closed when the existing opt-in preference is enabled. Polling uses sequential five-second ETag reads, pauses when hidden and ignores responses after disposal. Existing `ppgw-proxy-settings` fields and unrelated preferences survive. Group search/region/status/sort controls retain focus across refreshes; large groups show 120 cards at a time with search and further expansion. Node/provider strings are text, custom URLs accept HTTP/HTTPS without embedded credentials, and details omit arbitrary fields and credentials.
- `src/rules.js`, `rule-model.js`, and `rules.css` own the rules page. Direct visits use source modules without loading the compatibility runtime. Rules retain backend indexes, order, counters, temporary disable controls, search, pagination and the existing session page-size preference. Unknown or duplicate indexes cannot submit a toggle. Target groups support nested viewing and Selector switches; automatic and smart groups remain read-only here. Provider updates use encoded paths and stop queued updates on leaving. Active URL tests require an explicit submission and distinguish probe results from collected matching logs; ambiguous duplicate rules are not located. GEO updates require confirmation and report each file's actual result, including partial failures. Sequential 15-second refreshes pause when hidden, retain search focus, and abort on disposal. Read failures retain the list with disabled toggles. A 401 pauses operations; login refreshes state without replaying a mutation. Large lists default to 100 rows per page and group panels expand in batches of 120. API strings render as text, and narrow tables scroll within the card.
- `connections.js`, `traffic.js`, `distribution.js`, `logs.js`, and `region.js` own the remaining five routes. Shared `monitor-client.js` owns sequential polling, incremental SSE, connection/body timeouts, cancellation, visibility and authentication. Hidden/disposed pages stop reads; shared reauthentication only restarts reads. `monitor-view.js` and `monitor.css` provide text-only tables, pagination, confirmations, exports and responsive controls.
- Connections retain active/closed history (100 closed entries), counter-derived rates, filters, column preferences, copy controls and explicit close operations. Traffic retains full/domain/client views, time and column filters, expansion, CSV/JSON exports and confirmed clearing. Distribution retains node totals, rates and reset, plus client/service traffic, duration and connection rankings. Duration is the maximum observed span. Collection-disabled pages open no statistics streams.
- Logs retain independent core/screen search, local minimum level, safe ANSI colors, two-pane layouts, local clear/export, auto-follow and pause buffers. Each pane retains 2,000 lines, initially renders the newest 400, and offers all retained lines. Both streams collect while the log page is visible, including the pane not currently displayed; unavailable terminal output opens no terminal stream.
- `region-catalog.js` preserves all 59 upstream request/rule definitions; `region-engine.js` evaluates their dependency graph and verdict expressions. Detection is explicit, uses only the backend probe endpoint, caps requests at five and retries only HTTP 429 up to three attempts. Stop, hide, leave and 401 cancel active and queued probes. Results, IP masking, per-group/individual runs, details and reports remain available. Synthetic outcomes do not establish real service availability.
- Every route now uses maintained source. The public upstream bundle remains copied byte-for-byte as a packaging reference and is never imported by the application. The retired DOM/login/history bridge is removed. `legacy.html` redirects old bookmarks to the main entry. Tokens remain in Authorization headers and never enter URLs or messages.

Apply, source switching and backup/recovery previews appear inline at full content width. The original index CSS provides the established theme baseline. The builder only reads its standard `<style>` and module import entry. It does not patch compressed JS symbols. Updating the upstream theme or retained reference bundle requires reviewing style compatibility and detection-catalog changes.

Subscription management uses shared page tabs for policy editing, configuration sources, and recent operations. The source form and operation lists display directly in their tabs. Settings include a recent-operations tab; diagnostics use the same tabs and card spacing for runtime checks, backups/recovery, and recent operations. Switching tabs keeps editor/source drafts and pending task tracking. Tab controls support arrow keys, Home, and End, and scroll horizontally on narrow screens.

Historical failed settings jobs remain in Recent operations; reading configuration does not replay them as current error banners. Current submissions and resumed browser tasks still report their failures inline, and recovery-required warnings remain persistent. The runtime strip distinguishes the core's reported successful configuration load from a matching check of the running configuration and management services. It shows the check time, covered components and specific failure; stale identities wait for another check. The read-only Recheck action preserves drafts and never applies settings or restarts services. Background checks run every 60 seconds, and changed saved/runtime identities also request a check. These checks do not establish real client traffic or acceptance of unused assets.

## Synthetic browser acceptance

These scripts intercept all requests on synthetic origins and never contact a deployed gateway. Install Playwright separately or set `PPGW_PLAYWRIGHT_MODULE` to the existing Playwright module. Chrome is used through Playwright's `chrome` channel. Set `PPGW_PYTHON` to the Python interpreter that can import the repository's backend dependencies.

```sh
python -m unittest discover -s tests -p test_dashboard.py
node scripts/verify-dashboard-fixture.cjs frontend/dist
node scripts/verify-runtime-navigation.cjs frontend/dist
node scripts/verify-unified-runtime.cjs frontend/dist
node scripts/verify-overview-fixture.cjs frontend/dist
node scripts/verify-proxies-fixture.cjs frontend/dist
node scripts/verify-rules-fixture.cjs frontend/dist
node scripts/verify-settings-fixture.cjs frontend/dist
node scripts/verify-subscription-drafts.cjs frontend/dist
node scripts/verify-subscription-flow.cjs frontend/dist
node scripts/verify-source-editor.cjs frontend/dist
node scripts/verify-complex-editor.cjs frontend/dist
node scripts/verify-diagnostics-fixture.cjs frontend/dist
```

The dashboard build test checks the manifest hashes, untouched compatibility bundle, and byte-identical repeated builds. The existing browser suites retain their capability assertions with source DOM selectors: settings validation and recovery, mobile themes, back guards, source changes, provider refresh and schedule drafts, and backend-driven change previews. The source editor suite additionally edits real fields in both kinds and calls backend `validate_ppsub`, `feature_options`, and `merge_editor` on the submitted JSON, verifying preserved hidden credentials and unknown fields. It tests login on a non-secure HTTP origin, copied/moved/deleted rows, reauthentication with drafts, stored preferences, and ignored foreign navigation messages.

The diagnostics fixture verifies paginated integrity checks, invalid backup controls, allowlisted exports, explicit backup confirmation, signed restore/recovery previews, stale preview rejection, uncertain submissions, interrupted connections, same-ID reload/poll continuation, and pending navigation/logout/Back/unload guards. It separately checks definite submit-401 rejection versus polling-401 with a historical password, all acceptance states, the post-completion worker restart command, dark/light themes, mobile 320px layouts, and text-only rendering of untrusted values. A missing job never unlocks automatically: read-only diagnostics are shown, pending recovery prevents release, and an explicit human acknowledgement plus a fresh diagnostic check can stop this browser's tracking without a server mutation or replay. A new accepted job continues polling automatically while an earlier completed job's runtime refresh is delayed. Visible desktop navigation is checked against the complete free-mode route list and readable text bounds. The Node diagnostics tests independently check report projection and persisted job metadata.

Browser evidence and screenshots go under ignored `dist/`. No production API or real subscription is needed.

The shared-document runtime fixture visits all maintained runtime pages, asserting that each renders its own component without a reload or iframe. It checks theme/draft retention, browser Back/Forward, changed-password reauthentication through the shared login form, absence of duplicate floating tools and mobile width. The subscription fixture asserts title/toolbar/content ordering and full editor width at 1863px desktop and narrow mobile sizes, so an extra wrapper cannot silently turn into a second column. It also adds a node group and checks its desktop/mobile height. `src/editor.css` preserves the original PPsub card layout: compact controls, mode buttons, keyword/source/node chips, and small add buttons at the bottom. The update schedule expands inline. Token inputs commit on Enter or when leaving the field; untouched and unknown configuration fields retain their original values.

The proxy fixture checks read-only initial loading, encoded names, definite failures and duplicate submission, selector versus automatic behavior, native and smart locks, long presses, lock release before group tests, custom URL validation, provider updates, scoped connection closure, mode-only PATCH, ETag/error recovery, focus retention, allowlisted details, authentication without mutation replay and source-route Back/Forward. It also checks 60 groups and 1000 candidate nodes, bounded expansion, the final candidate through search, and 390px/320px layouts. `--baseline` captures the unchanged upstream proxy page from a separately built baseline tree. These are synthetic UI checks, not deployed-gateway or end-to-end traffic acceptance.

The rules fixture verifies indexed temporary toggles, duplicate submission and definite failure, global/rule mode, nested Selector and automatic/smart group behavior, provider updates, confirmed GEO partial failures, URL tests and log location, busy and unavailable responses, malformed-read recovery, authentication without mutation replay, search focus and preferences, source-route history, hidden/disposed lifecycle, and cancellation of queued provider updates. It checks 10,000 rules, 1,000 group candidates, paginated rendering, bounded expansion, and 390px/320px internal table scrolling. `--baseline` captures the unchanged upstream rules page from a separately built baseline tree. These synthetic checks do not establish real gateway or client traffic acceptance.

The five-page fixture (`scripts/verify-monitors-fixture.cjs`) runs a loopback HTTP/SSE server with synthetic records and blocks all external requests. It verifies connection history and close confirmation, traffic grouping/export/pause, distribution rankings/reset, safe ANSI and bounded log buffers, all 59 detection entries, throttling/concurrency/cancellation, reauthentication without write replay, disabled collection, unavailable terminals and desktop/mobile themes. `--baseline` records the unchanged upstream UI from a separately built baseline directory.
