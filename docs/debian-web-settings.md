# Web 使用说明

登录后通过侧栏进入 **订阅**、**设置** 或 **诊断**。桌面侧栏可收起并记住状态，手机使用抽屉菜单；底部外观按钮在系统、亮色、暗色之间切换。

| 分栏 | 日常用途 |
| --- | --- |
| 概览 | 运行摘要、流量、CPU/内存与网络接口 |
| 代理 / 规则 | 切换节点、测速、筛选、临时规则测试和数据更新 |
| 连接 / 流量 / 分布 / 日志 | 当前连接、记录、排行和实时日志 |
| 区域 | 手动检测当前出口的服务可用性；结果受目标服务与网络影响 |
| 订阅 | 编辑订阅、节点组与分流规则，管理配置来源 |
| 设置 / 诊断 | 配置预览应用、网关与 Mihomo 更新、运行核对、备份恢复 |

直接路径为 `/ui/#/settings` 和 `/ui/#/subscriptions`。旧 `/ui/gateway.html` 自动跳转并保留任务参数。首次安装的管理密码位置见[安装指南](debian-deployment.md)。下文是各项设置及应用边界的参考，需要时查阅即可。

在这两页之间切换会保留尚未应用的修改；离开到其他页面前会提示放弃草稿。应用任务执行期间请等待结果后再离开。

浏览器登录使用可撤销的 HttpOnly 会话，最长 12 小时，30 分钟没有认证请求后失效。升级后首次需要重新登录；刷新可恢复有效会话，修改密码、服务重启和退出登录会使会话失效。旧存储中的认证字段清空，其他偏好保留。远端管理脚本需要迁移到 Cookie 登录，协议和 HTTP/TLS 边界见[浏览器管理会话](browser-sessions.md)；独立观察 API 的 Token 不变。

页面顶部共用运行与操作状态区，展示实际运行模式、设置加载确认、本地策略加载状态及最近 20 次操作；后台保留最近 100 条脱敏记录。获取、校验、保存、应用、验证和回退按实际阶段显示。订阅任务结果会持久保存；辅助服务重启时，未完成任务保留原任务号并标为“结果待核实”，不会自动重复执行。设置加载确认使用已验证的持久版本与对应运行实例，核心和 Mihomo 策略分别核对；缺少验证依据时显示“暂时无法确认”。

## 安装和日常管理的分工

安装脚本负责依赖、网卡、初始认证、服务和升级恢复。新安装以 `free` 模式启动；显式代理、UDP、核心流量统计、IPv6、对外观测 API、历史采集和 Mihomo 自动更新默认关闭。保留随机管理密码及私网/回环访问范围。已有安装升级时保留原设置；旧配置未明确设置 `api.enabled=true` 时，观测 API 及其历史采集停止并取消自启。

日常配置在 Web 中按需修改。`ppgw-admin` 继续用于批量操作、备份恢复、安装升级和 Web 无法访问时的修复。低层 `install.py --enable-test-features` 保留为显式测试选项，正常安装不套用测试配置。

## 代理页面的隐藏设置

“页面设置”适用于全部节点组；组内搜索、筛选和测速地址在各组单独设置。组头可直接测速，展开“组内筛选与测速设置”查看更多选项。

在“代理 → 页面设置”中，可启用疑似订阅说明节点的自动隐藏，或在“自定义隐藏”中添加完整节点名、名称包含的关键词。关键词按普通文字匹配，不区分大小写；节点详情也可直接选择“隐藏此节点”。名单支持逐条恢复和清空，刷新后保留，仅在当前浏览器生效。

隐藏只影响节点卡片展示，不修改配置、当前选择或测速范围，节点组仍会显示。订阅节点名会变化时，可使用稳定的关键词。

规则页默认保留全部列，可在“列设置”隐藏统计详情列；规则测试和数据管理按需展开。订阅编辑默认展开每类首行，新增或复制行自动展开，保存区显示当前修改状态。布局说明见[页面整理记录](ui-layout-review.md)。

## 网关设置

“维护与 API”顶部的 **LovestGateWay 更新** 用于升级网关程序本身。“检查网关更新”读取本项目 GitHub 正式发行清单，显示当前/最新版本和发行说明；“升级 LovestGateWay”需要再次确认，只安装刚检查的版本。独立后台任务执行下载、摘要与架构校验、备份、安装和启动验收，沿用原配置及启动状态。刷新或断连后继续查询同一任务，不会重发安装；核心重启使登录失效时，重新登录即可查询结果。升级成功后刷新页面加载新版界面。检查结果有效期为 30 分钟，不提供自动降级。

下方的 **Mihomo 核心** 独立管理 Mihomo 的安装、CPU 型号与回退，两种更新不会互相替代。首次从旧版获得网关更新入口，仍需先运行一次 README 的安装命令。

| 页面 | 内容 |
| --- | --- |
| 访问与统计 | 管理密码、代理认证、管理/代理访问范围、显式代理开关、流量统计与上限 |
| 维护与 API | Mihomo 检查/更新/回退、自动维护、可选观测 API 开关、连接地址、专用 Token 及历史采集 |
| 网络与出站 | 网卡、IPv6、Web/DNS 监听、DNS/FakeIP、UDP、SOCKS5/OpenVPN、文件导入 |
| 高级选项 | BT/QUIC/未知流量阻断、转发阈值、自动选点和节点解析等兼容设置 |

先选择“预览变更”，核对字段和生效方式，再确认应用。密码和订阅链接不回显，留空保留已保存值。导入文件只保存资源，随后预览并确认模式/文件选择；覆盖当前使用的同名资源后，可用“重启应用资源”明确重载。

部分设置名称旁提供 **?** 说明入口。点击或用键盘 Enter / 空格展开，可在字段下方查看作用、适用条件和填写示例；再次点击收起。查看说明不会产生待应用修改，切换设置分区后保留本次展开状态。说明随面板主题显示，手机上可直接点击阅读。

DNS 上游地址也称信任 DNS，用于网关需要的本地解析；高级选项中的额外 DNS 服务器也称扩展 DNS，主要用于补充机场节点的解析结果。开启节点 DNS 预解析后，原生 PPsub 会保留原节点，并为可用 IP 增加入口副本；普通订阅和本地 YAML 的此功能需要 `fast_node=yes`。字段旁说明同时解释 FakeIP、核心流量统计与 API 历史采集的区别，以及自动选点、UDP 和订阅计划的适用范围。

配置应用复用脚本的类型校验、版本检查、备份、事务锁、加载验收与失败回退。配置已被其他操作修改时拒绝旧版本提交。Web 任务由 `paopaogw-settings.service` 独立执行，核心重启时仍能记录结果；浏览器以任务号恢复查询。修改管理密码后需重新登录。监听地址变化时提供新地址链接，链接仅携带公开任务号，不携带密码或 Token。

| 变更 | 应用方式 |
| --- | --- |
| 管理/代理 CIDR、管理密码、代理认证、转发阈值 | 仅热更新转发核心，不重新生成或加载 Mihomo 配置 |
| 记录上限、清理日 | 统计已开启时热更新，否则重启 |
| 对外观测 API 开关 | 启停 API 及其开机自启；关闭时同时停止 API 历史采集，不重启网关 |
| API 名称、探测白名单、监听、专用 Token | API 已开启且活动时仅重启 API；关闭时只保存配置；失败恢复原配置及 Token |
| 历史采集、自动更新 | 启停对应采集服务/维护定时器；历史采集同时受 API 开关控制 |
| 历史保留天数 | 采集开启时重启采集服务 |
| 模式、来源、分流策略、DNS、UDP、统计开关、网卡、监听、IPv6、时区、阻断项 | 重启网关；时区同时同步相关辅助服务 |

热更新验收检查核心 boot_id 不变、运行 revision 改变及实际配置快照；无法读取旧运行状态时改用重启。隔离 Debian 实测管理密码和统计参数热更新时已有代理连接继续通信；Mihomo 模式核心专用热更新保持核心 boot_id、Mihomo PID 和生成配置不变。该结果只覆盖已验证的变更路径，不代表所有设置均可无中断切换。

## 可选对外观测 API

在“网关设置 → 维护与 API → 对外观测 API”中使用“启用对外观测 API”开关。默认关闭，不监听 API 端口；仅保存监听设置不会自动启动服务。开启后启用服务及开机自启，关闭后停止 API 和它的历史采集，已有历史及 Token 保留。上述操作独立于 Web 设置、订阅管理和代理转发，失败时恢复原配置及辅助服务状态。

只在本机使用时保留 `127.0.0.1`。其他设备需要连接时，监听填写网关的实际局域网 IPv4 地址，端口默认 `8788`；文档示例为 `http://192.0.2.10:8788`。填写 `0.0.0.0` 表示监听全部 IPv4 网卡，客户端仍使用网关的实际 IP。页面显示地址预览，外部访问范围由宿主网络和防火墙控制。

点击“查看当前 Token”可复制专用 API Token。该操作只接受管理员登录凭据，响应禁止缓存，页面 60 秒后自动隐藏。API Token 与 Web 管理密码分开，只有观测和受限诊断权限。需要更换时填写 32–256 个无空格的 ASCII 字符，或点击“生成新 Token”生成 64 位十六进制随机值；在网关预览并确认应用后更新客户端。留空保留现有 Token。通用配置响应、预览和任务记录均脱敏，Token 保存在 `/etc/paopaogw/read-token`，不写入 `api.json`。

“API 历史采集”仅在对外观测 API 已开启时运行，保留期限由“历史保留天数”控制。它与概览和流量页面使用的“核心流量统计”分别控制。

## 订阅与策略

页面保持单页，依次展示当前配置来源、全局选项、配置内提供商、节点组与规则。主配置来源有三种：远程完整 Clash/Mihomo 配置、本地 YAML、原生 PPsub。先在“网关设置 → 维护与 API”安装 Mihomo，再导入或切换到所需来源。

| 来源 | 下方编辑保存位置 | 更新方式 |
| --- | --- | --- |
| 远程完整配置 | `clash-policy.json` 本地覆盖策略 | 按全局选项的计划更新主订阅，再合并本地策略 |
| 本地 YAML | 同一份本地覆盖策略，**不改写源 YAML** | 不展示主订阅更新计划；文件内提供商按各自设置更新 |
| 原生 PPsub | 本机 `ppsub.json` | PPsub 提供商与生成配置使用原有更新机制 |

“当前配置来源”显示文件名或主订阅 URL。该 URL 通过已有管理员专用订阅接口读取；通用设置响应、预览和持久任务记录继续脱敏。主配置订阅地址与下方“配置内节点提供商”地址含义不同：前者用于下载整份配置，后者属于该配置内部资源。

“切换配置来源”独立预览和确认，可选择远程配置地址、本机 YAML 或导入 PPsub JSON。切换前先保存或重新读取当前草稿；有旧本地策略或 PPsub 冲突时，界面在两个切换方向都显示备份和清除确认。来源任务成功后，编辑器重新读取新来源。导入 YAML 仅保存文件，随后在来源选择里预览并确认；覆盖同名资源可明确选择“重启应用资源”。

日常编辑使用右上角的**保存并应用**，先预览，再确认。全局监测、入站、定时重启、提供商、分组、规则及订阅更新计划作为同一事务保存，统一备份、加载验收和失败回退。读取失败、旧版本提交或快照超过 30 分钟时，需要重新读取；重新读取同时提示放弃编辑内容和更新计划。重新读取会同步更新编辑快照、设置值和版本；读取到不同版本时暂时禁止保存，可重新读取后重试。在订阅页与网关设置之间切换保留草稿；一页有草稿时，另一页暂时只读并提供返回原草稿的入口。原草稿保存、放弃或取消来源切换后，另一页恢复编辑。

预览按订阅提供商、节点组、规则订阅和规则列出应用前后数量及新增、删除、修改和顺序变化。对象名称最多展示各类前 20 项；规则仅展示数量，不显示规则原文、目标地址或凭据。完整配置中有稳定编辑身份的对象更名显示为修改；原生 PPsub 按名称匹配，更名显示为删除和新增。原生规则按规则块统计，手写规则另列行数；无稳定身份的规则替换按删除和新增统计。更新时间变化不计为配置内容修改。

来源区域列出与当前来源绑定的本地覆盖范围。完整配置的节点组、规则和提供商覆盖按整个区段保存，主订阅更新后继续合并这些本地修改；“恢复订阅原策略”可撤销覆盖。来源不匹配或策略无法读取时会明确提示，不能据此确认已应用。预览的生效方式来自后台实际计划：仅保存、调整辅助服务、核心热更新或重启。核心未运行时明确提示启动后加载；热更新条件不满足时可能改用重启，应用前会提示这一可能性。

完整配置模式保留原提供商的数量和名称，可编辑其 URL；新增、删除、复制、排序、更名及 PPsub 编辑导入等不适用入口隐藏。无 HTTP 提供商时隐藏该区域。节点组、RULE-SET 与手写规则继续可编辑，未展示字段、节点凭据、DNS 和其他顶层配置保留；不支持的“URL 下载”规则模式隐藏。原生 PPsub 继续支持完整的提供商结构操作与 JSON 编辑导入。

完整配置的“导出编辑内容”下载 PPsub 编辑数据，不能充当源 YAML 备份；**备份运行 YAML**下载当前已加载的完整 YAML，包含节点和凭据，不包含未保存修改。原生 PPsub 的导出用于保存其编辑 JSON。宿主完整安装备份和恢复继续使用 `ppgw-admin`；“恢复订阅原策略”可备份并撤销本地覆盖。

旧 `/ui/#/ppsub` 和带 `tab` 的旧地址自动归并到 `/ui/#/subscriptions`。核心检查、更新和回退统一放在“网关设置 → 维护与 API”。

## 服务与故障处理

原生 PPsub 的每个提供商显示已保存节点数、最近尝试、最近成功、下次更新时间及结果。失败尝试不会覆盖最近成功时间；计划由后台按实际调度逻辑计算。提供商更换 URL 后不继承旧来源的成功记录。更新取得相同的完整节点配置及 hosts 时，仅刷新缓存和结果，不重启网关；密码、协议参数、节点顺序或 hosts 改变仍走校验、加载验收及失败回退。账号流量、获取时间和 YAML 排版变化不会单独触发重启；不能可靠解析比较时保守执行应用。完整 Clash/Mihomo 配置仍沿用其现有提供商机制。

设置服务仅监听 `127.0.0.1:8790`，经现有管理员认证的固定 `/sniffbox/settings/` 路由转发。可选观测 API 的凭据不能操作配置，关闭观测 API 不影响设置服务。输入凭据不持久保存到 Web 任务元数据，备份本身包含配置凭据，继续仅由宿主管理员读取。

正常安装/升级自动纳入新服务；使用低层安装入口时手动启用：

```sh
sudo systemctl enable --now paopaogw-settings.service
```

失败回退会保留任务执行服务，避免它重启自身而丢失结果。若任务曾中断或提示需恢复，在宿主检查：

```sh
sudo ppgw-admin status
sudo ppgw-admin recover --yes
sudo journalctl -u paopaogw-settings --since '10 minutes ago'
```

服务未运行时，保存配置不会被标为已加载。外部配置冲突时不覆盖外部修改，需先核对持久文件与备份。备份和恢复详情见[脚本管理](debian-management.md)。


## 全新安装无法检查或下载 Mihomo

安装、更新或回退可能重启管理页面使用的监听服务。页面会保留本次维护任务号，短暂断连或服务暂不可用时自动重新连接，继续读取同一任务的结果；刷新或重新登录后也继续查询，不会自动重复安装。长时间未确认时显示“继续查询维护结果”。“正在重新连接”表示查询暂时中断，不能据此判断更新失败；最终以本次任务结果、实际核心版本和运行验收为准。

“尚未检查/待检查”表示没有取得官方稳定版信息。先点击“检查稳定版”；“安装 / 更新 Mihomo”本身也会先查询官方版本，不要求提前手动完成检查。全新安装默认关闭自动更新，因此不会在后台自动下载 Mihomo。

维护下载器由这台 Debian 直接访问 `api.github.com`、`github.com` 和官方跳转的 `release-assets.githubusercontent.com`。它不使用 HTTP_PROXY，也不经尚未安装的 Mihomo。管理电脑能访问 GitHub，不代表 Debian 机器能访问。检查成功后再安装；核对版本/摘要失败不会跳过校验。

维护操作失败会在页面显示中文原因和诊断码：`RELEASE_DNS_FAILED`（域名解析）、`RELEASE_NETWORK_TIMEOUT`（超时）、`RELEASE_NETWORK_FAILED`（连接失败）、`RELEASE_TLS_FAILED`（HTTPS，检查时钟/CA）、`RELEASE_RATE_LIMITED`（GitHub 限流），以及下载文件或版本校验失败。`metadata` 阶段表示查询版本失败，`download` 表示版本已取得但下载资产失败。操作状态保存在 `/var/lib/paopaogw/maintenance/operation.json`。日志不输出上游正文、凭据或完整 URL。

旧安装包仅显示通用“维护未完成”；可先在 Debian 本机执行以下只读检查，将输出用于定位网络或版本资产问题：

```sh
sudo python3 - <<'PY'
import json, sys
```

### 不依赖 GitHub 连通性的离线安装

在可信电脑取得 `lovestgateway-mihomo-offline-v1.19.33-amd64.tar.gz` 及其 `.sha256` 校验文件，拷到已安装网关的 Debian amd64。执行：

```sh
sha256sum -c lovestgateway-mihomo-offline-v1.19.33-amd64.tar.gz.sha256
tar xzf lovestgateway-mihomo-offline-v1.19.33-amd64.tar.gz
cd lovestgateway-mihomo-offline-v1.19.33-amd64
sudo sh install.sh
```

该包包含完整官方资产、固定 SHA256、许可证和独立维护入口，无需先升级网关包或在 Debian 下载额外文件。安装验证 ELF、实际版本、当前运行配置；原本运行的网关会重启一次并验收。原配置和自动更新开关保留；新版维护入口对相同二进制重复安装不重启，旧离线包可能仍按版本跳过替换。安装后刷新页面，再配置订阅。在线检查仍需 GitHub 网络连通性，离线安装不修复网络本身。

已更新的 `mihomo_update.py` 也提供 `install-local --archive 官方.gz --sha256 可信官方压缩文件摘要 --version vX.Y.Z`。该入口仅接受管理员明确提供的本地文件和可信摘要，不从文件旁边自动读取未确认摘要，不访问网络，并使用相同安装与回退事务。


### GitHub API 限流

诊断码 `RELEASE_RATE_LIMITED` 已在异地新安装问题中由现场命令确认。GitHub 对未认证公共 API 按出口 IP 共享配额，其他共用同一出口的设备也可能耗尽配额。官方说明：https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api 。离线安装成功只说明核心就绪，在线检查仍受此配额约束。

维护程序解析 `X-RateLimit-Reset` 与 `Retry-After`，在状态和页面中显示可重试时间；未到时间不会再次访问 API。成功取得且校验过资产名/URL/SHA256 的版本信息缓存五分钟，连续“检查→更新”及定时任务内部检查会复用信息。过期、损坏或不符合官方资产校验的缓存不会被信任为新版本。

已安装的核心可直接用于订阅或 YAML 配置，不需要反复点击安装。限流期间旧版页面仍会显示“待检查”和通用维护失败，新修复包显示“查询受限”和明确原因；页面时间按浏览器本地时区显示，命令行附带明确 UTC 偏移。限流恢复后重新检查，不能承诺固定等待一小时必然恢复，应以实际响应头或修复版提示为准。本次没有接入第三方镜像，也不引入跳过校验的下载路径。


### 首次导入后代理菜单刷新

全新直连模式登录后，从“订阅与策略”切换/导入来源并成功应用，网页会重新读取实际运行模式并同步侧栏；进入订阅/YAML 模式后立即显示“代理”和“规则”。切回直连模式后相应入口隐藏。订阅编辑保存、核心安装更新后也会刷新运行状态。导入为草稿或尚未通过应用验收时，不提前改变运行模式或导航。

修复前可出现后台已加载节点和代理组，但侧栏仍沿用登录时直连模式的情况。首次加载升级后的网页可能需要浏览器刷新一次，以取得新的脚本；之后导入并应用无需重新登录来刷新菜单。


### 网页本地更新 Mihomo

网关设置 → 维护与 API → Mihomo 核心 → 本地文件更新（手动）。从 https://github.com/MetaCubeX/mihomo/releases 下载对应稳定版、适用于本机 CPU 的 Linux amd64 `.gz`；不确定时选择 v1（旧名称 compatible）。选择文件，填写 `v主版本.次版本.修订版本` 和该资产对应的官方 64 位 SHA256，点击“上传并安装 Mihomo”。文件名含版本时自动填写，仍可修改。SHA256 应来自可信官方发布信息，服务端不会联网替用户确认摘要来源。

此流程不请求 GitHub API，也不依赖在线稳定版检查成功。一次文件最多 64 MiB；每块最多 16 KiB（编码后兼容原生入口的 32 KiB 请求上限），通过已有管理认证、同源检查和固定 loopback 转发入口提交，不开放文件路径或任意命令接口。上传时显示进度，服务端检查完整长度与 SHA256，再由独立 systemd 任务安装。需要替换时沿用 ELF 架构、实际版本、配置检查和启动验收失败回退；完全相同的二进制跳过替换和重启，同版本的不同 CPU 构建允许手动替换。网页刷新不会中断已经提交的安装，再次打开维护页会读取并跟踪后台结果；尚未提交的上传需要重新选择文件。暂存上传最多两个，过期暂存会在下一次上传时清理。

安装可能重启网关；网关配置、订阅、管理密码和实例身份保留。查看后台：`systemctl status paopaogw-core-action@install-local`，或 `journalctl -u paopaogw-core-action@install-local -n 50 --no-pager`。旧页面需先升级网关完整包并强制刷新，单独的 Mihomo 离线核心包不包含此网页功能。

### Mihomo CPU 自动选型

维护页的“Mihomo CPU 型号”默认自动，按 Debian 系统实际确认的指令集选择 v3、v2 或 v1。检测使用 glibc 的系统能力判断，包含操作系统对 AVX 状态保存和虚拟机暴露指令集的支持；检测失败保守使用 v1。虚拟机以内部检测结果为准，迁移后重新检查。管理员也可指定 v1/v2/v3；未确认支持的高等级会被拒绝。配置字段为 `maintenance.core_variant`，取值 `auto`、`v1`、`v2`、`v3`，旧配置未包含此字段时自动使用 `auto`。

保存型号只修改维护设置，不重启或替换当前核心；之后点击“检查稳定版”或“安装 / 更新 Mihomo”。页面分别显示当前核心型号和所选目标，无法从 Go 构建信息识别的现有型号显示未识别。官方资产优先使用 `mihomo-linux-amd64-v1/v2/v3-vX.Y.Z.gz`；v1 在旧 Release 中兼容查找 `compatible`，不会固定依赖这个已被官方标记为旧名称的别名。

定时维护只安装尚未安装的核心或升级更高的稳定版，不因同版本型号不同而重启。手动点击安装 / 更新可切换同版本型号；当前版本比官方稳定版更高时不会在线降级，实验版或无法识别的现有版本不被自动覆盖。缓存的 Release 元数据每次重新按当前 CPU/设置选择资产，所有型号都保留官方 URL、SHA256、实际运行版本、配置预检和启动验收。官方说明见 [Mihomo 文件说明](https://wiki.metacubex.one/startup/faq/) 与 [Go CPU 等级](https://go.dev/wiki/MinimumRequirements#amd64)。


### 设置和修改管理密码

全新交互安装时，脚本提示输入管理密码（输入隐藏，至少 8 个字符），并要求再次确认。直接回车使用 8 位随机密码；`--yes` 非交互安装继续自动生成 8 位随机密码。计划和日志不打印密码明文。升级不会再次要求设置，也不会覆盖原密码。

网页进入“网关设置 → 访问与统计 → 修改管理密码”，填写“管理密码”和“确认新管理密码”，再点击底部“预览变更 → 确认应用”。空白表示保留原密码；长度不足或两次不一致时不能提交。预览与任务记录隐藏密码内容，输入不会写入草稿会话存储。应用后旧登录失效，用新密码重新登录即可；待确认的任务号会继续保留供登录后查询。


### 每个机场分别设置更新计划

原生 PPsub 的每个订阅提供商都可设置“跟随全局计划”“仅手动更新”或“自动更新”。独立自动计划可填写 `30m`、`6h`、`1d` 等间隔；跟随全局时使用全局间隔或每日指定小时，全局默认仅手动不会禁止其他机场的独立自动计划。计划修改与下方订阅、节点组和规则一起保存并应用；导入、导出 PPsub 也保留 `update_mode` / `update_interval` 字段。

“更新此订阅”只请求该机场；顶部“更新全部订阅”立即请求所有机场，包括仅手动机场。存在未保存修改时需先保存或放弃。自动调度每 30 秒检查一次，启用或更换计划后等待完整间隔，最后尝试时间持久保存，失败后仍按该机场间隔重试。每日指定小时的跟随计划在下一次对应时点执行。重启和修改策略始终读取已保存节点，不额外访问机场；更新失败、空响应或候选校验失败继续保留旧节点。

例如“提供商 A”选择仅手动，“提供商 B”和“提供商 C”分别选择自动、间隔 `1d`，即可独立控制各提供商的更新。新添加或更换 URL 的仅手动提供商，需首次手动更新以获取节点。

### 统一任务与轻量状态轮询

设置、订阅和 Mihomo 维护共用安全操作历史，保留原 API 的 `status`，并增加公共 `phase`（执行阶段）、`result`（结果）和 `recovery`（是否需要核实）。每项工作绑定执行服务、systemd invocation、系统 boot ID 与进程启动时刻；重启管理服务或异常退出后，未确认完成的工作显示“中断，结果待核实”，保留原任务号且不自动重放。新请求使用新任务号。历史保留最近 100 条，仍存活的执行实例暂不清理；无绑定的旧活动项不会永久阻止清理。

管理员专用 `GET /sniffbox/settings/status` 返回运行采样、事务恢复标记及统一任务历史；每轮只请求一次核心信息，不返回完整配置、配置 schema 或秘密值。完整配置仍通过原 `/settings/config` 按需读取。配置内容摘要按文件元数据缓存，覆盖基础设置、额外配置与资源目录；增删、替换、mtime/ctime/size/inode 变化会使缓存失效。为发现刻意保持元数据的外部修改，最多 60 秒强制重算一次；无法可靠采样或核心不可达时不会宣称已加载。

`GET /sniffbox/subscription/providers` 只返回提供商的更新时间、节点数、计划与结果，不访问核心。页面空闲时每 5 秒刷新这些状态，自动调度或另一浏览器完成更新后可见，且不会导入配置或覆盖未保存草稿。较大的节点缓存仅在元数据改变时重新解析，内存只保留脱敏状态投影。

维护执行仍使用独立 systemd oneshot，核心重启不终止其结果记录。排队身份只能由对应 action/unit 的新 invocation 领取；遗留 `running` 必须先核实执行实例。旧版维护 API 将排队映射为 `running`、中断映射为 `failed`，同时保留 `phase=interrupted/result=unknown/recovery=check_required`，避免旧页面将中断误报为成功。恢复保存文件与验证运行成功分别记录，未验证的回退明确要求人工核实。

新增固定路由需要升级 Rust 核心与页面、Python 管理模块，单独替换前端不能启用这些接口；升级核心需要一次重启。

### 运行状态重新核对

设置服务启动后与运行期间自动重新核对，页面读取到保存版本、核心启动标识或运行配置摘要变化时也会触发核对。周期为 60 秒，失败后保留原始结果并重试，不重放历史任务。“订阅与策略”和“网关设置”的状态栏显示最近核对时间、范围与具体未确认原因；“重新核对”可立即执行一次，不重新读取表单或清除未保存草稿。

管理员专用 `POST /sniffbox/settings/recheck` 只接受空 JSON 对象，要求管理员认证。设置和订阅入口会在 loopback 转发前核对浏览器提供的 Origin 与 Host，拒绝外站、空来源值和重复来源头；不发送 Origin 的已认证命令行客户端仍可使用。核对拒绝越过待恢复事务，但不占用管理写入锁，不会阻挡正在提交的设置操作。核对前后校验保存版本、事务状态和核心身份，变化时不签发新的成功记录。操作只读取运行状态、写入私有核对记录，不应用配置、获取机场订阅、更换核心或重启服务。

核对范围为当前运行的网关 INI、服务启动环境、管理服务运行状态，以及启用时的观测 API 身份和 Mihomo 来源/本地策略。原生 PPsub 比较保存文档与运行副本，本地 YAML 比较实际使用的私有副本；远程来源只核对已加载来源和策略，不检查远端是否有更新。不改变管理员选择的开机启动计划。未使用的导入资源、OpenVPN 资源加载、真实客户端 DNS/透明 TCP/UDP/IPv6 业务不在此成功结论内；无法确认的活动资源继续显示待核对。旧核对记录与当前核心身份不匹配时标明等待重新核对，不作为当前成功证据。

### 可维护的页面源码

登录、导航、主题、网关设置和订阅编辑器从 `frontend/` 构建，保留原有配置格式、任务服务和草稿保护。现有运行概览、代理、规则等页面通过同源兼容页保留；原上游脚本按原字节复制，不再修改压缩后的内部函数。构建需要 Node.js 18 或更新版本，服务器运行这些静态页面不需要 Node 服务。

登录失效时可在原页面重新登录，未保存编辑继续保留。导入文件的迟到读取结果不能覆盖读取期间的新编辑；切换页面或重新读取配置也会使旧导入结果失效。

### 诊断与恢复

“诊断与恢复”使用现有管理员身份，独立于对外观测 API。页面按需读取固定服务状态、配置来源、最近失败原因和事务恢复状态；“导出脱敏报告”只包含这些固定字段，不导出日志、配置正文、地址或凭据。本机状态正常不能证明所有客户端的 DNS、路由和透明转发正常。

备份列表按页校验实际文件摘要，只有校验通过的备份可以进入恢复预览。预览区分配置、资源、程序、服务定义和运行数据的增删改数量，并列出恢复后的服务状态、连接中断、历史密码和程序版本变化。完整备份可能恢复旧密码与令牌；恢复后需要使用恢复出的密码重新登录。局部配置备份只恢复其登记文件，不移除无关文件。

恢复预览有效五分钟。确认时服务端在管理锁内重新核对持久配置、程序、服务状态、目标备份和事务记录；过期或状态改变必须重新预览确认。持续变化的运行数据库不参与预览版本比较，但备份数据仍进行实际摘要校验。恢复前创建救援备份；失败时回退，只有服务状态和目标核心/API 的实际响应通过验收后才报告成功。

创建完整备份也会暂停受影响服务以保证一致性，随后恢复原服务状态并验收，执行前会提示活动连接可能中断。Web 任务期间保留管理任务服务，任务号在刷新或重新登录后继续查询；通信失败仅显示结果待核对，不自动重复执行恢复。暂存环境的结果明确显示未执行真实服务验收。

查询不到任务时保留原任务号，不自动认定失败或重新提交。先从管理脚本与状态记录核实任务没有执行或已经结束；页面再次确认没有待恢复事务后，可明确选择仅解除本机追踪。该操作不会取消服务端任务，也不代表任务已成功。

管理任务服务是 Web 恢复的保留项。若备份记录的该服务 active/enabled 与当前不同，预览和结果会明确显示仍保留当前状态；需要完整还原其运行与开机状态时，应从服务器使用 CLI 恢复。其他服务按预览中的目标状态恢复并验收。

恢复若替换了管理程序或该服务的单元定义，正在执行的管理服务仍使用原来已载入的代码或启动设置。先确认任务终态与验收结果，再在服务器执行 `sudo systemctl restart paopaogw-settings`，刷新页面核对版本。中断事务可从页面单独预览恢复；如页面或已安装程序不可用，使用可信发布包中的 `install.sh --recover --yes` 恢复，参见脚本管理文档。
