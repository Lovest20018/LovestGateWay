# 后续优化与交付方案

## 已完成：Mihomo 自动选型与统一发行包

默认按系统实际支持的 CPU 等级选择 Linux amd64-v3、v2 或 v1。Debian 的 glibc loader 同时检测 CPU、操作系统与虚拟化环境；没有明确检测结果时使用 v1。允许管理员指定较低等级；未确认支持的高等级拒绝安装。选型改变只保存设置，点击安装 / 更新才替换同版本核心。

官方资产优先匹配明确的 v1/v2/v3 文件名；v1 允许回退到旧 compatible 名称。旧名称可能从未来 Release 移除，因此不能继续固定为 compatible。只接受官方稳定版、准确资产名、官方下载地址和 SHA256；缺少资产或摘要时停止安装，不猜测下载链接或跳过校验。

更新判断使用数字版本比较：未安装可安装，只有更高稳定版属于自动升级；相同版本的 CPU 型号变化独立提示，由管理员手动安装。已安装版本较新不自动降级；无法识别的现有版本保留并提示。手动离线上传允许同版本换型，完全相同的二进制不重启。候选必须实际运行版本检查、通过配置预检和启动验收，失败沿用原核心。

验证范围：CPU 等级和检测失败、型号设置保存、官方资产匹配、缓存重新选型、数字版本比较、同版本换型、离线重复安装、损坏下载拒绝和启动失败回退；网页覆盖桌面/手机、草稿保护和状态说明。完整包从同一提交构建 Rust、Python 和最新前端，并校验源码、产物与安装清单。补做干净安装、升级保留配置以及失败回退，避免完整包落后于独立 UI 更新。

官方依据：

- [Mihomo 文件说明](https://wiki.metacubex.one/startup/faq/)
- [Mihomo 构建矩阵](https://github.com/MetaCubeX/mihomo/blob/Meta/.github/workflows/build.yml)
- [Go amd64 最低要求](https://go.dev/wiki/MinimumRequirements#amd64)

自动选择策略由本项目根据官方等级定义实现；官方没有保证更高等级在所有负载下都更快。

## 后续验收与迁移

运行状态核对闭环与完整发行包已完成：核心更新、重启或恢复后重新核对当前运行配置和管理服务，记录核对时间与范围，并提供保留草稿的“重新核对”入口。完整包已同步页面分栏、历史错误提示和核对功能；同一提交的干净安装、升级保留配置、失败回退与中断恢复验证通过。真实客户端业务验收独立记录，不以核对通过替代。

1. 复杂 UI 使用验收已完成：12 个提供商、60 个节点组、200 条规则、1000 个节点候选，原生 PPsub 和完整 Clash 配置在 1440px 桌面与 320px 手机的四组验证通过。后台刷新与页签切换保留草稿，末尾分组的复制、排序、删除及保存正常，未编辑字段和隐藏凭据保留，无页面报错或横向溢出。紧凑卡片、标签和三个外观按钮保留。可通过 `scripts/verify-complex-editor.cjs` 复验。
2. 网络验收分层记录：同版本发行包的隔离网关已完成 FakeIP DNS、IPv4/IPv6 透明 HTTP、普通 UDP、UDP/443 回显与透明入口连接证据，以及订阅更新、失败保留和中断恢复的 17 项管理检查；配置恢复与测试环境清理另行核对。`scripts/verify-native-network.py --fixture-only` 可复验隔离转发范围。真实客户端端到端验收继续待完成：在独立客户端环境检查 DNS、透明 TCP/UDP、IPv6、机场更新后的业务访问。隔离转发、显式代理和本机 API 不能代替这项验收；UDP/443 回显也不代表完整 QUIC 协议通过。业务出口失败或缺少公网 IPv6 条件时如实记录，不据合成检查宣称整体通过。
3. 运行页面逐步迁移：概览已接管为可维护源码，覆盖流量、CPU、内存、接口、配置和连接池，刷新、认证、主题和 320px 手机布局已验证；代理、规则、连接、流量、分布、日志和区域继续逐页迁移。每次迁移保留原有交互并做桌面/手机比较。概览当前为待发行源码，41 仍运行上一发行版。
4. 代码同步：通过公开源码与凭据检查后同步远端；部署记录、真实配置和验收证据继续留在 Git 之外。
5. 通用 Mihomo 热加载继续保持实验状态。只有各类变更的连接、凭据、缓存和回退行为都有证据后才启用，不能仅依据 HTTP 204 判断成功。
6. FakeIP DNS 已增加 TCP 监听，与 UDP 共用地址池；支持连接复用、分段帧及流水查询，并限制连接数和收发时间。安装预检同时检查 TCP、UDP 端口，任一监听失败时拒绝核心启动。验收仍需排除其他 DNS 服务或透明代理代答，再分别记录 UDP 与 TCP 结果。

每一步按实际验收结果更新状态，不把安装成功等同于完整业务链路通过。

冷重启节点选择覆盖问题已在源码修复，并使用隔离 Mihomo 验证；保留原有健康失败后的自动选点。该修复与概览迁移均未部署到生产。[机制与复验](node-selection-persistence.md)。
