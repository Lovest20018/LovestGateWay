## 本轮已完成

| 范围 | 当前实现 |
| --- | --- |
| 观测正确性 | 合法连接快照中的 `null`、`[]` 均作为本次空记录；畸形响应、网络及认证错误仍报告失败；API 与采集器共用校验 |
| 历史采集 | 复用 SQLite 连接，合并同轮成功读取的来源事务，仅超限时扫描淘汰；保持每秒采样、保留期限和 10 万条上限 |
| 代理接口与页面 | 共享不可变 JSON、预计算 ETag、合并并发抓取、失败保留最近有效快照；页面复用节点卡片、标签和曲线，折叠组延迟处理 |

| 侧栏与内容区 | 紧凑分组、收起记忆、单按钮外观切换；11 个分栏统一标题、工具栏、反馈和表格操作，手机布局及复杂编辑回归通过 |

## 已有验证

- 本轮功能基线的 Linux Python 361 项、前端 36 项通过。性能与兼容改动完成 Rust 1060 项通过、5 项原有用例忽略；最近纯布局交付重新完成 release 构建，未再次执行 Rust 全量单测。
- 布局交付从完整安装包运行 13 组浏览器验证，覆盖桌面、320/375px 手机、亮暗主题、两种订阅编辑模式，以及 60 组、1000 个节点候选。
- 同提交完整包完成隔离新装、升级保留与原生部署核对；安装文件和实际 HTTP 页面资源与包内摘要一致。私有运行记录不进入公开仓库。
- 隔离网络覆盖 FakeIP DNS、IPv4/IPv6 透明 HTTP、普通 UDP 和 UDP/443 回显。本机 DNS 回读与服务状态核对已完成，这些结果不代替真实客户端的完整业务验收。

## 性能测量的适用范围

下列为同数据、同测试条件的合成对比，不代表实际转发吞吐：

| 场景 | 基线 → 优化后 |
| --- | --- |
| 历史写入：1 万条已有记录、两个来源各 500 条、30 轮 | 测试磁盘中位约 95.5 → 50.1 ms；累计写入约 61.3 → 38.1 MB，记录摘要一致 |
| 代理页面：60 组、1000 候选、主组 120 张可见卡片 | 刷新中位约 104.7 → 46.3 ms；主组每轮子节点变更 726 → 0 |

复验入口：`scripts/benchmark-observer.py --baseline <旧版 history_store.py>`；`scripts/verify-proxies-fixture.cjs <前端构建目录> --performance --evidence=<输出目录>`。测试只使用合成数据。
