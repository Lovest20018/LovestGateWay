## 已有验证

- v0.2.7 在隔离 Debian 环境验证了 `free` 和 `suburl` 的 TCP、UDP 长连接，覆盖手动清零、月度清零和清零后字节累计。浏览器回归覆盖 API 地址预览和设置回滚。正式包全量测试结果见对应的 Actions。
- v0.2.6 发布前本地 Python 375 项、前端 36 项通过（Windows 的 4 项平台相关用例跳过），设置、历史概览与管理登录浏览器回归通过；Linux 全量 Python、Rust、浏览器和真实 PPsub CLI 合成故障切换由正式发布 CI 重新执行，实际结果以对应 Actions 为准。
- 此前性能与兼容基线完成 Rust 1060 项通过、5 项原有用例忽略；这属于此前证据，不代替当前提交的 CI。
- 布局交付从完整安装包运行 13 组浏览器验证，覆盖桌面、320/375px 手机、亮暗主题、两种订阅编辑模式，以及 60 组、1000 个节点候选。
- 同提交完整包完成隔离新装、升级保留与原生部署核对；安装文件和实际 HTTP 页面资源与包内摘要一致。私有运行记录不进入公开仓库。
- 隔离网络覆盖 FakeIP DNS、IPv4/IPv6 透明 HTTP、普通 UDP 和 UDP/443 回显。本机 DNS 回读与服务状态核对已完成，这些结果不代替真实客户端的完整业务验收。

## 性能测量的适用范围

下列为同数据、同测试条件的合成对比，不代表实际转发吞吐：

| 场景 | 基线 → 优化后 |
| --- | --- |
| 历史写入：1 万条已有记录、两个来源各 500 条、30 轮 | 测试磁盘中位约 95.5 → 50.1 ms；累计写入约 61.3 → 38.1 MB，记录摘要一致 |
| 代理页面：60 组、1000 候选、主组 120 张可见卡片 | 刷新中位约 104.7 → 46.3 ms；主组每轮子节点变更 726 → 0 |

复验入口：`scripts/benchmark-observer.py --baseline <旧版 history_store.py>`；`scripts/verify-proxies-fixture.cjs <前端构建目录> --performance --evidence=<输出目录>`。测试只使用合成数据。

## 尚待完成与独立后续

- **运行告警跟进**。节点拨号拒绝、超时和整组测速失败按时段、出站、目标核对。GeoIP 下载持续失败时检查现存数据能否加载。
- **真实客户端业务验收**：从独立客户端验证 DNS、透明 TCP/UDP、订阅更新后的业务访问与实际代理出口。缺少公网 IPv6 条件时明确保留待测；UDP/443 回显不证明 QUIC 协议通过。
- **上游依赖评审**：台账仍暂缓上游 `Cargo.lock` 更新，需单独评估兼容和安全影响，见[上游跟进](upstream-maintenance.md)。
- **更深层性能优化**：连接聚合锁、TCP/UDP 参数和整体转发吞吐先按真实负载剖析决定，没有依据时不改变网络参数。

自动测试方法见[测试与验收](testing.md)，本轮 UI 实施结果见[UI 优化结果](ui-optimization-plan.md)。
