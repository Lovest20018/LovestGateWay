# Mihomo 热加载期间的新连接测量

这是 R2 的隔离测量结论，不是生产无中断验收。使用 Mihomo Meta v1.19.33 linux amd64，SHA256 为 `817f50b3ac6a8b1c4360c5cf2961906057f3a883d970ebbcb0028a01632b620f`，在无外网、无生产挂载、无宿主端口映射的独立容器运行。

## 方法

`scripts/measure-mihomo-selection-window.py` 复用产品 `reload_verified` 路径。选中节点、其他节点与 DIRECT 各返回不同字节，因此成功连接到错误出口也能检出。覆盖 rule/global 模式及 REJECT、DIRECT、其他节点三种组默认项；始终启用 `profile.store-selected`。每个场景先验证 20 条新连接健康，然后保持一条长连接，在 12 次静态规则加载期间由两个线程持续建立新连接。另加 PUT 应答后人为等待 50ms 的压力组，明确区别于自然延迟。

## 2026-11-06 结果

自然组每行均执行 12 次热加载，既有长连接每次仍返回正确出口字节；未加载期间的基线连接全部健康。

| 模式 | 默认项 | 期间新连接数 | 失败数 | 错误出口数 | 最大 PUT 应答至回读完成 |
| --- | --- | ---: | ---: | ---: | ---: |
| rule | REJECT | 138 | 57 | 0 | 43.812ms |
| rule | DIRECT | 147 | 55 | 0 | 48.650ms |
| rule | 其他节点 | 136 | 58 | 0 | 34.236ms |
| global | REJECT | 143 | 61 | 0 | 38.812ms |
| global | DIRECT | 142 | 59 | 0 | 35.746ms |
| global | 其他节点 | 150 | 55 | 0 | 38.224ms |

自然组共 856 次新连接，345 次失败、0 次错误出口；50ms 压力组共 1,694 次，355 次失败、0 次错误出口。两组的失败表现合计为 676 次 EOF 和 24 次连接重置。压力组既有长连接也全部保留。

这些连接集中在反复加载期间，不能把上述比例当作生产故障率。“PUT 应答至回读完成”包含 controller 调用、恢复选择和核验耗时，不等于默认节点窗口长度或精确断流时长。此次没有复现成功连接误走默认出口，不能据此证明所有负载都不会发生选择窗口；也没有进一步定位 Mihomo 内部的新连接失败原因。

## 执行决定

保留现有节点选择恢复、显式 DIRECT 及 GLOBAL 回读，不更改下发顺序，也不以 `store-selected` 替代验证。该选项已经启用，仍有新连接失败，不能把它作为零中断修复。界面预览明确说明新建连接可能短暂失败；受限静态规则优化可以继续实施，但不扩展 provider、凭据、DNS、监听或动态组的热加载范围。保证每条新连接无缝接入需要另行验证核心行为，未在本轮宣称实现。

## 复现

仅在一次性隔离环境运行；固定回环 SOCKS 端口为 19080，`--work-dir` 必须不存在。脚本生成含单调时间戳、每条连接出口/错误、加载时点与二进制摘要的 `report.json`。

```sh
python3 -B scripts/measure-mihomo-selection-window.py \
  --binary /fixture/mihomo --work-dir /experiment/new-selection-run
```

脚本退出 0 表示测量流程与基线/长连接断言完成，报告中的 `failed` 仍是实际观察到的新连接失败，不代表无中断验收通过。
